## Separately authorised live acceptance sequence

1. Review the existing-record import preview and consistent backup; approve only resolved facts and history mappings.
2. Start the managed browser and foreground runtime using UPGRADE.md. Select one actual application and its exact tab; keep its final action at REVIEW first.
3. Confirm supported upload acceptance, saved sections, resume and manual completion for the specific portal. Unknown portal mechanics require further adapter implementation and new synthetic tests before qualification.
4. If optional mailbox verification is wanted, provide the desktop OAuth client configuration and separately authorise mailbox access. Passwords and employer account creation remain manual. OAUTH_SETUP.md describes the scope and disconnect behavior.
5. Record successful synthetic qualification from the current CI report, then authorise a supervised real application with its exact account, content and final-action grant. Record its matched receipt as supervised evidence. Explicit unattended enablement is a subsequent decision.

No live acceptance permissions are assumed by this handover. The approved development work does not deploy a service, perform live employer actions or start assessment automation. The follow-up user request authorises publishing code to GitHub; private profile facts were updated separately and stay ignored.
