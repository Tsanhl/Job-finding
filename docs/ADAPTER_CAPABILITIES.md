# Capability and evidence matrix

“Implemented” describes executable code, not universal portal support. Live verification is **No** throughout this development run.

| Capability | Implemented | Synthetically tested | Live verified | Blockers / limits |
|---|---|---|---|---|
| Four function requests, per-target final action, global reservations | Yes | Compatibility, target authority, runtime, fencing and concurrent socket tests | No | Actual employer sessions need supervised acceptance |
| Hidden CV upload + server attachment evidence | Yes | Real Chromium at 1/2/5/10 workers | No | Unknown upload widgets require handoff |
| Transcript, cover letter, writing sample selection | Yes, registry and semantic slots | Same upload handler; format/hash/applicability checks | No | Actual portal-specific widgets not certified |
| Grouped questions, per-target progress, manual completion | Yes | Two real browser contexts; grouped resume; actual foreground process/CLI restart | No | Later conditional questions may add a focused follow-up |
| Signature precedence, limits, optional unknown fields | Yes | Real Chromium and legacy regression suite | No | Personal decisions remain manual |
| Repeated record Add/Save reconciliation | Yes, qualified adapter contract | Fixture contract; source record helpers | No | Named AllHires/Apply4Law editors and structured Workday editors are implemented; unrecognised tenant layouts remain handoffs |
| AllHires / Apply4Law | Ordinary fields, saved attachments, named Save/Continue and repeated-record actions, final submission/receipt contracts | Real Chromium form POST, record dedup and submit/receipt tests for each family | No | Live tenant qualification remains required; unknown IDs/APIs are not guessed |
| Workday | Ordinary fields, widget/upload mechanics, application-scoped save/navigation, review/submit/receipt contracts | Isolated Workday controls, draft-identity binding, non-final save, final action and role/account/reference checks | Supervised form/status shapes only | Applicant performed final submission; tenant differences still require supervised acceptance |
| Greenhouse / Ashby / Lever | Ordinary fields + known attachment selectors | Shared generic engine | No | Filename-only indicators do not establish server acceptance; navigation/submission require handoff |
| SmartRecruiters / Taleo | Ordinary fields | Shared generic engine | No | Custom records/navigation/submission not certified |
| Native Keychain broker | Yes, Security framework | Memory-secret integration; no native secret access | No | User-authorised native acceptance still required |
| Gmail OAuth | Connect/status/refresh/disconnect/revoke, cancellation fencing, PKCE/state/loopback | Simulated consent, identity/scope, state mismatch, revocation and cancelled connect | No | User Cloud client, consent and native token storage acceptance required |
| Account registration + verification transactions | Pending credential, pre-request transaction, matched email, consume-once reconciliation | Complete synthetic service flow | No | Exact account/verification policy; employer-specific acceptance required |
| AUTO submit + receipt + restart | Yes | Fixture end-to-end and Workday-shaped contract | No | Qualification gate remains; unknown workflows stay review-only |
| Bounded discovery | Bright Network, registered Workday/AllHires/Apply4Law roots, explicit feeds/pages, same-site vacancy-link traversal, area filtering and CHECK PORTAL summaries | Four-provider and listing-to-detail normalized/persisted fixtures | No | Source blocking and tenant shapes may require a browser handoff; eligibility needs review |

| SQLite migrations, backup/restore, cache | Yes | Disposable databases, constraints, recovery and backup restore | No live migration | Explicit preview/backup/import approval required for existing records |
| Streamlit dashboard | Yes | AppTest and automatic status refresh; separate foreground/socket test | No live user session | Run foreground owner/runtime to use managed tabs |

The supported positive path is concrete and tested locally; this matrix deliberately does not claim every ATS control is supported. Unsupported controls remain visible, resumable handoffs. No blanket unattended qualification is installed.

See [acceptance limits](ACCEPTANCE_LIMITS.md) for requirements that remain partially implemented or await separately authorised live evidence.
